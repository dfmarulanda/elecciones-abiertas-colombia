# Official source access audit · 2026-08-03

This audit answers a technical question: can the configured 2026 presidential second-round sources be collected anonymously and reproducibly without bypassing an access control? It does not grant legal permission or replace a review of the official sites' current terms.

Checks were performed between 22:40 and 22:56 UTC on 2026-08-03. No unredacted election form is committed to the repository. The later checkpointed 2026 crawls for both rounds remain incomplete; scrutiny is retained as raw, unclassified material only. This audit does not claim that either crawl is complete or that a real 2026 release can be published.

## Remaining implementation gap

`source-check --full-crawl` intentionally refuses to run without an explicit, separately reviewed crawl plan. The dedicated pre-count planner/crawler, raw-byte storage before parsing, coverage accounting, and national crawl are implemented. The full-scope mesa crawls for both 2026 rounds run resumably at 2 requests per second per host, with protocol retry and no keepalive connections; neither is complete. Full scope means attempting every planned identifier, not that every mesa is retrieved or that coverage is 100%. Scrutiny remains raw/unclassified; department, municipality, and zone aggregate collection is implemented but is not run concurrently with the mesa crawl.

Before a full release, complete and verify:

1. The full place/mesa plan and crawl, using only identifiers observed from official place results.
2. A scrutiny-index planner that joins only exact key/value pairs from the fetched manifest snapshot, plus a resumable normal-session browser-download adapter for the allowlisted CNE SharePoint files.
3. Independent human double entry of vote fields; OCR or assisted reading is never authoritative by itself.
4. Reconciliation, statistical/FDR validation, and public-product gates.
5. Public-output redaction gates. The CNE forms include signatures and identification fields; originals stay externally linked, and no unredacted derivative may enter a public release.

## Publication consequence

The CNE E-26 is a verified candidate source, so a national-only candidate release can be built locally. No real release is activated by this audit. National totals must be double-entered from the document, reconciled with compatible official scrutiny, assigned immutable provenance, and pass every coverage, wording, privacy, statistical/FDR, and product gate first.

The transport supports `ETag` conditional `GET` (`304`) and byte ranges. It did not expose CORS, pagination, a usable `OPTIONS` response, or a published rate limit; the collector uses one conservative client and conditional rechecks. It accepts only the reviewed Observatory HTTPS host, rejects unexpected redirects/content types/sizes, validates a single non-encrypted ZIP member and compression ratio, stores raw ZIP bytes by SHA-256 before parsing, and emits deterministic Parquet plus metadata. Every raw fact, derived rollup, and geography node carries its source URL, retrieval time, content hash, parser/transform versions, data version, `contextual_baseline` source type, and `context_only` legal status. The candidate manifest remains non-active; it is not a pre-count, scrutiny, final declaration, or integrity signal.

### Immutable release migration and honest coverage

The former fixed `historical-2022-mmv-context-v1` candidate cannot safely identify the hardened schema/provenance transform. It is retained untouched and the builder explicitly refuses to put v2 files in its directory. New builds must use an isolated directory named for the inactive v2 candidate ID, of the form `historical-2022-mmv-context-v2-<identity-hash>`, derived from the two raw content hashes and retrieval times, parser/transform versions and profile, and Git commit. Its manifest `created_at` is the latest frozen source retrieval time, not the build clock. Thus frozen inputs generate byte-identical Parquet, metadata, and manifest artifacts; a changed source, parser, profile, or commit gets a new identity rather than overwriting v1 or another fixed release.

The CLI now stages the complete build under the ignored release root, verifies the returned deterministic ID, and atomically installs the artifact directory and matching manifest filename. Repeating the same build compares all staged bytes and reports a no-op; a collision with different bytes is refused. The reviewed frozen-input candidate is built with:

```console
uv run --project pipeline elecciones-pipeline historical-2022-build \
  --git-commit frozen-control-2026-08-04
```

That command creates the non-active candidate at `data/releases/historical-2022-mmv-context-v2-705d3d71523003b8/` and `data/manifests/historical-2022-mmv-context-v2-705d3d71523003b8.json`. The large release directory remains ignored. Loading, publication, deployment, and editing `current-release.json` are separate operations; the loader now requires explicit matching `--manifest` and `--release-dir` arguments and has no v1 default.

The release-manifest coverage vocabulary has no `unknown` expected denominator. Consequently each reviewed ZIP source object is honestly recorded as `expected=1`, `retrieved=1`, `parsed=1`, with no claim about national mesa completeness. The 103,364 distinct mesas in each file are separately labelled **observed snapshot scope**, while complete expected-mesa coverage remains unknown. No registered-elector or turnout value is inferred.

The candidate artifacts are not exposed through the current production API. A separate indexed FastAPI/PostgreSQL import and query adapter is the intended runtime path; it must not be described as querying Parquet files directly or as an upstream JSON proxy. There is no documented, fast public JSON API for this 2022 material: immutable official ZIP snapshots plus the indexed service are the correct design.

The reviewed NOSUPERUSER loader proof completed the initial import in 352.33 s and an identical no-op in 2.06 s, loading 241,652 facts/geographies, 206,728 round-scoped mesa rows, and 1,349,277 categories. Local SQL execution samples were 0.052 ms for a page, 0.119 ms for a mesa with categories, and 11.952 ms for a conservative cold national query. These are database execution measurements, not end-to-end API, network, cache, or browser latency promises.
